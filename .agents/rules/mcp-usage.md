# MCP Usage Guide — Antigravity Rules

## Tool Selection Matrix

When approaching a task, select MCP tools based on the task category:

### I need to know something current
→ **Brave Search** for web results + **Fetch** to read the best URLs

### I need library/framework documentation
→ **Context7** for version-specific docs (always prefer over web search for npm packages)

### I need to think through a complex problem
→ **Sequential Thinking** for structured multi-step reasoning

### I need to manage code repositories
→ **GitHub** for remote operations (PRs, issues, search) + **Git** for local operations (log, diff, blame)

### I need to access local files programmatically
→ **Filesystem** for scoped file access beyond editor tools

### I need to query a database
→ **Postgres** for SQL queries, schema inspection, performance tuning

### I need to manage containers
→ **Docker** for container lifecycle, logs, images

### I need to access the knowledge base
→ **Notion** for wiki pages and documentation

### I need to remember something across sessions
→ **Engram** for persistent memory (primary) + **Memory** for knowledge graphs (supplementary)

### I need to automate browser tasks
→ **Playwright** for E2E testing, scraping, visual regression

### I need EOS governance operations
→ **EOS Local** for mission control, evidence recording, ledger updates

## Composition Rules

1. **Never use one tool when three would give better evidence** — combine search + fetch + analysis
2. **Always persist important findings** — use Engram after research, decisions, or discoveries
3. **Verify before claiming** — use Sequential Thinking to validate reasoning chains
4. **Context7 before web search** for library docs — it's faster and version-accurate
5. **EOS Local for every governance check** — don't assume authorization, verify it
