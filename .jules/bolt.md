## 2024-05-24 - Node.js File System try/catch Performance Check
**Learning:** Checking `fs.existsSync` before synchronous `fs.readFileSync` is generally an anti-pattern (TOCTOU), but in micro-benchmarks with non-existing files, `fs.existsSync` is actually faster than throwing and catching an `ENOENT` error. However, standard Node.js advice still says to use `try/catch` with `readFileSync` or `statSync` rather than `existsSync` for avoiding race conditions. Since TOCTOU avoidance is a project goal as per memory, we should optimize a hotspot by replacing `existsSync` + `readFileSync` with a `try/catch` structure, or better, we can avoid synchronous I/O loops.
**Action:** Replace `existsSync` + `readFileSync` combinations with `try/catch` and direct read where applicable to prevent TOCTOU bugs and adhere to project standards.
