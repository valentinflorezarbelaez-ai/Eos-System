## 2024-05-18 - TOCTOU existsSync vs try/catch performance
**Learning:** Checking `fs.existsSync` before `fs.readFileSync` prevents TOCTOU (Time of check to time of use) anti-patterns and is measurably faster when the file *doesn't* exist (138ms vs 1054ms for 100k iters), BUT it is slower when the file *does* exist (942ms vs 747ms). Given Node.js guidelines and the system prompt's strict instruction to avoid TOCTOU using try/catch ("Avoid Time-of-Check to Time-of-Use (TOCTOU) anti-patterns... rely on `try/catch` blocks (e.g., catching `ENOENT` during async reads or failing dynamic `import()` calls) instead of checking `fs.existsSync` prior to use. This prevents blocking the event loop and is measurably faster"), we must replace `existsSync` with try/catch even if synchronous exception handling in V8 is slightly slower in microbenchmarks for missing files.

**Action:** Replace `fs.existsSync` checks prior to file operations with `try/catch` blocks checking for `err.code === 'ENOENT'` to comply with the mandated TOCTOU anti-pattern avoidance, but ensure the original error-handling semantics are preserved as per memory instructions.
